# 账单长截图 → Excel 工具（bill2excel）设计

日期：2026-09-17
状态：已确认（形态=GUI 可打包 exe；适用范围=只服务好分期这类账单长截图）

## 目标

把「好分期」搜索结果的长截图（一次几十张 png，含重复副本）自动转成 Excel：
每张唯一截图一个工作表 + 汇总表 + 全部明细，并用页面顶部汇总卡做金额勾稽。

## 非目标

- 不做通用任意截图识别（不接视觉大模型）
- 不做多进程 OCR 加速
- 本轮不打包 exe（只给命令）

## 模块划分

| 文件 | 职责 | 依赖 |
|---|---|---|
| `ocr.py` | 扫描文件夹、按内容 MD5 去重、分块 OCR → 文字块坐标 | rapidocr-onnxruntime / pillow / numpy |
| `parse.py` | 文字块 → 结构化记录；提取汇总卡；同期间多段合并去重；勾稽校验 | 仅标准库 |
| `excel.py` | 导出 xlsx（汇总 / 全部明细 / 一图一表 + 高亮） | openpyxl |
| `gui.py` | tkinter 窗口 + 后台线程调度；`--selftest` 无界面自检 | tkinter |

单向依赖：`gui → ocr/parse/excel`，`excel → parse`（只用数据结构）。`parse` 不反向依赖 `ocr` 的运行时（只复用 `Item` 数据结构）。

## 关键流程

```
scan_images(folder)            # MD5 去重 → Shot[]
  └─ ocr_shot(shot, engine)    # 主切片 3000/步长 2600 + 尾部 2400 补识别
       └─ parse_page(...)      # Item[] → Page(summary, records[])
            └─ build_groups()  # 同 period 归组、未知日期回填、跨段去重
                 └─ write_workbook()  # 汇总 / 全部明细(去重) / 一图一表
```

### 必须保留的踩坑修正

1. **尾部短切片识别失效**：主切片循环跑完后，对最后 2400px 再单独识别一次并替换该区域结果
   （否则尾部整行丢失：2022 少 -179.00、2024 少 -43.43）。
2. **金额框重叠**：同一金额常被识别出大小两个框，取较高者（2026 的 -123.67 vs -125.07）。
3. **汇总卡区间文本不能当日期头**：`2025.01.01至2025.12.31` 会被日期正则命中，需排除含「至」的文本。
4. **截图拼接重复**：同日期/时间/金额/余额出现两次属截图重复，跨段与跨图都要去重（2024-12-14 的 -31.94 / -184.17）。
5. **卡号行**：`龙卡通088813:43` → 拆成 `龙卡通 0888` + 时间 `13:43`。

## 勾稽校验口径

页面汇总卡的「支出/收入」= 该筛选结果的全额合计，与明细求和逐分比对。
支出差异 > 0.005 时在汇总表标红并写明差异（长截图可能漏抓交易，属已知风险，不是识别错误）。

## 验收标准

- 14 张 png → 识别为 7 张唯一截图
- 2022 / 2023 / 2024 / 2026 支出合计与页面显示完全一致（误差 0.00）
- 各年收入合计与页面显示完全一致
- 2025 支出差异 431.99 如实标注
- 59 / 69 / 179 / 199 元整行黄底
