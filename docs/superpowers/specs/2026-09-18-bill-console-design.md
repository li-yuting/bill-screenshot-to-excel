# 共用控制台 + 工具2（收支详情单页）设计

日期：2026-09-18
状态：已确认（启动台必显 / 卡片式入口 / 日志默认折叠）

## 背景

已有工具1：`bill2excel`，处理「好分期」多段长截图 → 一图一表 + 汇总。
新增工具2：处理银行 App 的「收支详情」单页截图 → 明细 + 多维汇总。
两者版式、字段、输出结构完全不同，需要一个**共用控制台**让用户选择用哪一个。

## 交互（已确认）

1. **每次打开都先显示启动台**（不记忆上次选择）
2. 启动台用**卡片式**入口：每张卡写明「适用什么截图 + 输出什么」
3. 进入工具后是**共用的操作页**：截图文件夹 / 高亮金额 / 开始转换 / 进度 / 打开结果
   - 日志区**默认折叠**，窗口压小；点一下展开
   - 左上「← 换一种账单类型」返回启动台

## 代码组织（不新开仓库，直接扩展现有目录）

```
bill2excel/
├── ocr.py        # 共用：扫描 + MD5 去重 + OCR（高度 ≤3000 的单屏图走单次整图识别）
├── parse.py      # 工具1 解析 + 合并勾稽
├── excel.py      # 工具1 导出
├── gui.py        # 工具1 入口（保留 run_pipeline 供控制台调用）
├── detail.py     # 工具2：解析 + 校验 + 多维汇总导出 + --selftest
├── console.py    # 控制台：启动台 + 操作页 + 工具注册表（新入口）
├── run.bat       # 改为启动 console.py
└── build_exe.py  # 改为打包 console.py
```

不在工具1和工具2之间抽公共库：两者只有「扫描去重 + OCR」真正共用（已在 `ocr.py`），
Excel 样式常量各留一份（十来行，比跨模块耦合便宜）。

## 工具2 解析规则

页面字段：顶部大金额（带符号）、余额、交易卡号、交易账户、交易户名、交易时间、
业务摘要、交易场所、交易金额。折叠区「查看全部」里的字段当前截图取不到，不解析。

- 顶部金额：`y < 400` 的金额文本中取字号最大的一个
- 余额：取含「余额」文本里的数字
- 7 个字段：左列标签 → 同一行（|Δy| < 25）最右侧的值
- 交易时间 `2026-02-0112:10:31` → 拆成日期 + 时间

### 三道校验（逐笔 + 整批）

1. 每笔「交易金额」必须等于顶部金额绝对值 —— 不等则记异常并单列
2. 7 个字段缺一不可 —— 缺则记「缺失字段」
3. 卡号 / 账户 / 户名 出现多种取值时列出 —— 提示可能混入了别人的截图

## 工具2 输出

- `明细`：序号 / 交易日期 / 交易时间 / 金额(元) / 业务摘要 / 交易场所 / 交易后余额 /
  交易卡号 / 交易账户 / 交易户名 / 源文件
- `汇总`：概览指标 + 按年 + 按月 + 按金额档 + 按业务摘要 + 按交易场所 +
  校验结果 + 文件对照（重复文件 → 唯一截图）
- 金额命中高亮档（默认 59 / 69 / 179 / 199）的整行黄底

## 验收标准

- 45 个文件识别为 43 张唯一截图（2 对 MD5 重复）
- 43 笔全部通过「交易金额 = |顶部金额|」校验，0 字段缺失
- 金额合计 8,097.00 元，时间范围 2023-05-09 → 2026-05-07
- 控制台启动台必显、日志默认折叠、两工具都能跑通
