# 账单截图转 Excel 控制台 设计

日期：2026-09-18
状态：已确认（方案 A + 共用控制台；启动台必看、卡片式、日志默认折叠）

## 目标

把两类版式完全不同的账单截图放进同一个入口：启动台选类型 → 对应的识别工具 → Excel。

## 非目标

- 不把两个解析器合成一个自动分流（版式差异大，分开更好维护）
- 不做与「账单1」的跨集勾稽、不做图表
- 不做多进程 OCR 加速

## 界面

一个 tkinter 窗口，两个 Frame 切换：

```
启动台（每次打开都先看到，不记忆上次选择）
  ├ 卡片：好分期账单长截图 —— 多段长截图 · 一图一表 + 汇总
  └ 卡片：收支详情单页     —— 每图一笔 · 明细 + 多维汇总
        ↓ 点击卡片
操作页（外壳完全共用，只有参数与日志文案不同）
  ├ ← 换一种账单类型（返回启动台，同时收起日志）
  ├ 截图文件夹 + 浏览
  ├ 高亮金额（默认 59, 69, 179, 199）
  ├ 开始转换 / 打开结果文件 / 显示日志 ▾ / 状态
  └ 进度条 + 日志区（默认折叠，窗口 320px；展开后 600px，跑完自动展开）
```

## 模块

| 文件 | 职责 | 依赖 |
|---|---|---|
| `app.py` | 控制台 GUI + CLI + `--selftest`；`ToolSpec` 注册表 | tkinter |
| `ocr.py` | 扫描/去重/OCR | rapidocr / pillow / numpy |
| `statement.py` | 工具一解析（长截图） | 仅标准库 |
| `detail.py` | 工具二解析（收支详情单页） | 仅标准库 |
| `excel.py` | 共用样式 + 两个导出函数 | openpyxl |

依赖方向：`app → {ocr, statement, detail, excel}`，`excel → {statement, detail}`；
两个解析模块只用 Protocol 描述文字块，不 import OCR，因此可脱离 OCR 单测。

## 关键解析规则（工具二）

页面：顶部大金额（支出为负）+ 余额，下方 7 行固定「标签 —— 值」，值右对齐到 x2≈1060。

- 顶部金额：y < 550 区域里的纯金额块中取字号最大者
- 余额：含「余额」的块取数字
- 7 个字段：同一行（|Δy| ≤ 30）里 **右边界最大** 的块（值右对齐，所以不能按左边界取）
- 三道自动校验：①「交易金额」==｜顶部金额｜ ②7 字段齐全 ③卡号/账户/户名取值唯一

## 输出（工具二）

- `明细`：序号/交易日期/交易时间/金额/业务摘要/交易场所/交易后余额/交易卡号/交易账户/交易户名/源文件
- `汇总`：总览 · 按年 · 按月 · 按金额档 · 按业务摘要 · 按交易场所 · 自动校验（含重复文件对照）

## 验收标准

- 启动台每次都先出现；选中后进入操作页；日志默认折叠
- 45 个文件 → 43 笔交易；金额一致性 43/43；字段缺失 0
- 工具一回归：2022/2023/2024/2026 支出与页面汇总卡仍完全一致
